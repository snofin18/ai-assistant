# TASK-331　zstd 安全公告修复

- 状态：**Done**
- 阶段：1　子阶段：**Stage 1c 安全前置**　批次：治理池　依赖：TASK-330 提交前门禁
- 本文件 = 卡片正文 ＋ 执行记录（ADR-0031）。

---

**目标**

把现有 `assistant-storage` 的 `zstd` 依赖从 `0.13` 最小升级到修复版 `0.14.3`，
消除 RUSTSEC-2026-0391 / 0398 / 0403 / 0410，并保持 blob 池业务代码与 API 用法不变。

**In scope**

- `crates/storage/Cargo.toml` 的既有 zstd 版本约束。
- `Cargo.lock` 中 zstd / zstd-safe / zstd-sys 的解析结果。
- `docs/DEPENDENCIES.md` 中 `zstd` 已批准版本及升级理由。
- storage 专项测试、workspace tests、fmt/clippy 与 `cargo deny check`。

**Out of scope**

- 不新增 crate、不替换压缩算法、不修改 `storage-design.md` 的 level 3 口径。
- 不修改 storage 产品代码、公共 trait、schema、ErrorCode、IPC/DB schema 或 CI。
- 不处理 TASK-330 的 CSV 逻辑。

**必须遵守**

1. 只升级既有依赖，不扩大依赖面。
2. 版本升级后必须由 lockfile 证明 zstd-safe / zstd-sys 达到公告修复范围。
3. 不得通过 `deny.toml` ignore、删除 advisory 或放宽门禁获得绿色。
4. `cargo deny check` 全类别通过后才能合并。

**验收命令**

```powershell
cargo test -p assistant-storage
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo test --workspace
cargo deny check
cargo run -p xtask -- hygiene
cargo run -p xtask -- check-migrations
```

**DoD**

- [ ] `zstd` 解析到 `>=0.14.3`，`zstd-safe` / `zstd-sys` 处于公告修复范围。
- [ ] storage 专项与 workspace 测试全绿。
- [ ] `cargo deny check` advisories / bans / licenses / sources 全绿。
- [ ] 依赖登记表与 lockfile 一致。

### 5. 偏差

- RUSTSEC 公告在 TASK-330 收口时才由在线 advisory DB 暴露；为解决仓库级 CI 阻塞，
  单独建立本安全前置卡，未把依赖升级混入浏览器功能卡。
- crates.io 直连超时；使用本机既有 `127.0.0.1:30000` HTTP(S) 代理完成索引与包下载。

### 6. 更合理做法

- 只升级既有压缩依赖的兼容主版本，保持 `zstd::bulk::compress/decompress` 和 level 3
  口径不变；不替换压缩算法，不放宽 `deny.toml`。
