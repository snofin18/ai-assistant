## 2. 环境探测与工具偏差（如实记）

- 第一步按 prompt 要求做能力探测并显式声明 `shell: "powershell"`：
  `Get-Command cargo,rg,gh` + `$PSVersionTable` **零输出挂起**（等待 25 s 未返回）。
  随后并行探路：默认 `bash`（WSL2）**正常**；`cmd.exe` 正常。
- 为确认是「PowerShell 整体不可用」还是「某条命令慢」，直接以绝对路径再试两种 PowerShell：
  `/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe -NoLogo -NoProfile -NonInteractive -Command 'echo PS51-OK2'`
  与 codex 自带的 `pwsh.exe -NoProfile -NonInteractive` —— **两者都在 60 s 超时前零输出**
  （`timeout 60` 杀掉后只留下 `head` 的退出码）。这与 skill
  `ai-assistant-automation-round` 里记的「2026-10-13/14 rounds 11-12：powershell 与 pwsh 全部挂起」
  是同一形态，故按该 skill 的 escape hatch 处理。
- 处置：`taskkill /F /IM pwsh.exe /T` + `/IM powershell.exe /T` 回收残留进程
  （成功终止 5780 / 26740 / 6636 及其子进程），随后**全程改用 WSL2 bash + 绝对 Windows exe 路径**：
  `/mnt/c/Users/fexfe/.cargo/bin/cargo.exe`、`/mnt/c/Users/fexfe/tools/bin/gh.exe`、
  `/mnt/c/Users/fexfe/AppData/Local/OpenAI/Codex/bin/ce4759538b7f2f1a/rg.exe`，
  文本处理走 `grep` / `sed` / `tail` / `wc`（WSL 自带）。
- 实测该路径可用：`cargo 1.98.1` / `gh version 2.101.0` / `ripgrep 15.2.0` 均在 0.5 s 内返回。
- **后果与边界（诚实记录）**：本 run **没有**按 prompt 原文使用 `shell: "powershell"`；
  所有验收命令都通过 Windows 侧 `cargo.exe` 真跑，输出与 PowerShell 路径等价（同一二进制）。
  本卡不含 `.ps1` 验收命令（覆盖率 / 门禁 / 适配包校验都不需要 PowerShell），
  因此这次偏差没有削弱任何证据。
- 另一个环境陷阱（已绕过）：`shell: "bash"` 由外层以 `bash -lc "<整条命令>"` 包装，
  因此命令里的 `$var` 会被**外层**先展开（早期一次 `for p in ...; do "$p" --version; done`
  被展成空串而报 `failed to run command ''`）。后续所有命令改为**不含 `$`**，
  需要机械改写状态文件时改用 `sed -f <脚本文件>`（脚本文件由 `apply_patch` 写入，避开引号层）。
