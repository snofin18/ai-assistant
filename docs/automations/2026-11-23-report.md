## 3. TASK-395 产品阻塞

`DRIFT-395-1` 仍是唯一产品实现阻塞：ADR-0108 要求 T2.1 handler 保留现有 `ErrorCode`
分类，但 `assistant_tool_bus::ToolBusError::error_code()` 当前不能无损表达
`TargetAmbiguous`、`PlatformPermission`、`VerifyFailed`、`Fatal` 等类别。把四个纯逻辑
handler 直接桥成 `ToolHandler` 会迫使实现用 `Transient` 或 `Fatal` 冒充，因此生产桥接停止。

该问题涉及公共接口，automation 不自行修改。TASK-395 保持 **Blocked**，四 Tool 未进入
`tools.json`，也未注册生产 ToolBus。Windows COM runner、ownership journal、独立 watchdog、
真实 `.xlsx` 与人类在场验收仍属后续阶段。

`DRIFT-395-2` 记录 22:00 槽位试图新增 round 3 报告时，该路径不在 TASK-395 write scope。
本轮没有追改旧卡 scope，而是创建 docs-only TASK-396 承载报告路径；原始 DRIFT 仍保留为审计
发现，不声称已被回溯消除。
