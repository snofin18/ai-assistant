# docs/memory/ — 长期记忆的分层存储（ADR-0021 落地版）

> **一句话**：`MEMORY.md` 只是**索引**（≤150 行）。具体条目在本目录的 L1/L2 文件里。
> **为什么这么分**：单个会话真正相关的记忆通常只有 2~5 条，而单体 `MEMORY.md` 要求每次
> 全量读入约 200 行 —— 读取成本与命中率不匹配，还会挤占任务上下文
> （本项目已因上下文问题撞过 ContextLimit，见 `LEDGER.md` 2026-09-17）。

## 层级

| 层 | 文件 | 装什么 | 何时读 |
|---|---|---|---|
| **L0** | `MEMORY.md`（仓库根） | 状态快照、四种记录文件的分工、条目格式、更新职责、**路由表** | **每个会话开始必读** |
| **L1** | `facts.md` | `[FACT]` 已验证事实（按主题分节） | grep 优先，按主题节读 |
| **L1** | `pitfalls.md` | `[PITFALL]` 跨应用的坑 | grep 优先，按主题节读 |
| **L1** | `rejected.md` | `[REJECTED]` 已否决方案 + 理由 | ★ **动手前全量读**（最短的一个） |
| **L1** | `decisions.md` | `[DECISION]` → ADR 编号索引 | 要知道"为什么这么定"时 |
| **L1** | `open.md` | `[OPEN]` / `[ASSUMPTION]` | 规划与裁决时 |
| **L2** | `apps/<app>.md` | **某一个应用**的版本/进程模型/UIA 形状/文本约定/性能/坑/通道/未测项 | 接该应用时**全量读** |
| **L3** | `archive/` | 仅当某个 L1/L2 文件 **> 400 行**时按主题拆出的部分 | 一般不读 |

## 读取路由（AGENTS.md §3 启动协议引用本表）

| 你要做什么 | 读什么 |
|---|---|
| 任何工作开始前 | `MEMORY.md`（L0，含快照与路由） |
| 动手前防止重复辩论 | `rejected.md`（全量） |
| 接某个应用 | `apps/<app>.md`（全量）+ `target-apps-feasibility.md` §3 对应档案 |
| 查某类事实 / 坑 | `facts.md` 或 `pitfalls.md` 的对应主题节（**先 grep，再局部读**） |
| 查为什么这么定 | `decisions.md` → `docs/adr/NNNN-*.md` |
| 查还有什么没定 | `open.md` |

## 三条写入规则（违反即缺陷）

1. **应用专属 → 只进 `apps/<app>.md`；跨应用 → 只进 L1。** 同一结论不得在两处都写正文；
   L1 需要提及时写**一行指针**（`→ 见 apps/notepad.md §4`），不复制内容。
2. **只追加，不改写他人条目。** 更正 = 新条目 + `[supersedes:YYYY-MM-DD]` 标注，
   原条目**保留**（它记录了"我们曾经以为"，这本身有价值）。
3. **归档按体积不按时间。** 触发条件是"单文件 > 400 行"，不是"条目太老"。
   理由：记忆价值不按时间衰减 —— 2026-09-16 的「GNOME 50 已移除 X11 后端」
   比 2026-09-18 的某条实测数据更长期有效；按时间归档会先扔掉最稳定的结论。

## 为什么不用 Codex 自带的 `~/.codex/memories/`

评估结论：**不作为项目事实源，仅作个人环境备忘**。理由（详见 ADR-0021 的对比表）：
不随仓库版本化、不能被 opencode / Claude Code 共享、含本机路径与隐私因而无法开源、
不在 AGENTS.md 的裁决链内、且需要显式请求才会写入。
若某天它支持仓库内路径 + 版本化 + 跨 agent，重新评估（已在 `open.md` 登记一条）。
