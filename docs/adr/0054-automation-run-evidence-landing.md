# ADR-0054　自动化轮次产物的唯一命名与「先落地，再自删」

状态：**Accepted**（2026-09-26，人类 chat：「执行」= 授权本 ADR 的两条规则 + 授权回填搁浅证据）　日期：2026-09-26　Supersedes：—　Superseded by：—
关联：`docs/automation-charter.md` §11.3 / §11.4 / §11.11、`docs/automations/codex-automations-operations.md` §4.1.b / §4.1.c、ADR-0046（一次性自动化的 7 条规格）、ADR-0049 / ADR-0050（最小间隔与开始时刻互斥）、ADR-0051 / ADR-0052（去夜间化）、ADR-0031（一卡一文件）、ADR-0041（计划文件可写面）、ADR-0028（`guard` 锁）、`tasks/TASK-206-storage-memory-fts5-search.md` §5（DRIFT-206-1）

## 背景（为什么现在要决定）

2026-09-26 按人类指令建了两个一次性自动化（14:15 `ai-assistant-1415-drift028-landing-then-next-card`、16:15 `ai-assistant-1615-next-card`）。**两轮都跑完并成功自删**，但暴露两个**章程 ↔ 实际执行**的缺口：

| # | 现象（一手复核，2026-09-26） | 影响 |
|---|---|---|
| 1 | 14:15 那轮领 TASK-206 后命中 **DRIFT-206-1**（新增迁移必须先占 `docs/storage-design.md` §3.4 的全局版本号，而该文件不在 write scope），按铁律 9 停止编码，写下执行记录 9 节 + `LEDGER.md` 一行 + **PL-091** + pitfall 条目，提交在**本地分支** `codex/task-206-storage-memory-fts5-search`（`d3ef5cb`）—— 但**没有 push、没有开 PR**，随后**自删**了自己 | 该轮**全部留痕**只存在于一个未合并的本地分支：`main` 上看不到 `DRIFT-206-1` 的卡片记录、看不到 `TASK-206 Blocked` 的 LEDGER 行、看不到 PL-091 与那条 pitfall。下一个会话（或干净 clone 的自动化）会**重新撞同一堵墙** |
| 2 | 两轮都写了 `docs/automations/2026-09-26-round-1.md`：§11.3 的「轮次 N = `round-*.md` 文件数 + 1」被 16:15 那轮按**工作区**文件数计算，而工作区里正是 14:15 那轮**未合并**的 `round-1.md` | 撞号 → 14:15 那轮的轮次记录被 16:15 那轮的**覆盖**，从 `main` 消失 |

两轮产物对照（一手）：

- **14:15 轮**：TASK-206 停在 DRIFT-206-1 → **产物搁浅**（未 push / 未 PR / 未合并）。
- **16:15 轮**：跳过被阻塞的 TASK-206，实现 TASK-028 → PR #62（merge `89189da`）→ CI 证据 PR #63（merge `227cbed`）**已进 `main`**。

人类 2026-09-26 指令「执行」= 授权本 ADR 的两条规则，并授权把 14:15 轮的搁浅证据**回填**进 `main`（与本 ADR 同一 PR）。

## 决策（一句话）

**自动化 run 必须先把自己这一轮的留痕落到 `main`（经 docs-only PR）再自删；且轮次编号只按 `main` 上的 `round-*.md` 计数** —— 两条缺一不可。

## 决策细化

| # | 内容 |
|---|---|
| **D1** | **「先落地，再自删」**：run 的**最后一步仍是自删**（ADR-0046 / 手册 §4.1.b 不变），但在自删**之前**必须确认本轮留痕已在 `main`：若本轮**产生了任何留痕**（任务卡执行记录、`LEDGER.md` 行、`docs/PARKING_LOT.md` 行、`docs/memory/*` 条目、轮次产物、阶段报告）却**没有**可合并的 PR，则**必须先开一个 docs-only PR**（按 ADR-0046 A6 的判据合并）**再**自删 |
| **D2** | **D1 的唯一例外**：本轮**完全没产生留痕**时才可直接自删。判据 = 「`git status` 干净 **且** 本轮未写任何 `docs/**` / `tasks/**` / `LEDGER.md`」。注意：§11.2 的 `-skipped.md` **本身就是留痕**，故走 D1。不确定时**一律按 D1**（从严） |
| **D3** | **轮次编号的唯一事实源 = `main`**：章程 §11.3 的「轮次 N」按 **`main` 上** `docs/automations/<运行日日期>-round-*.md` 的文件数 + 1 计算，**不得**按工作区文件数计算（工作区可能含未合并 / 未跟踪的轮次产物）。取数方式 = 先 `git fetch` 再 `git ls-tree --name-only origin/main -- docs/automations/`（或 `main`）；**不得**用 `Get-ChildItem` / `ls` 直接数工作区 |
| **D4** | **轮次文件不得覆盖**：写 `<运行日日期>-round-<N>.md` 前必须确认该路径在 `main` 上**不存在**；若已存在（并发 run 已占用该号），**顺延**到下一个未占用的 N，**禁止**覆盖既有轮次文件。阶段报告仍按 §11.4 原文：已存在则**更新**它，**不得**新建 `-report-2.md` 之类的副本 |
| **D5** | **回填例外（一次性）**：14:15 轮的搁浅产物按人类 2026-09-26 授权**回填**进 `main`；因 16:15 轮已占用 `round-1`，回填的轮次产物命名带运行标识后缀 = `2026-09-26-round-1-run1415.md` / `2026-09-26-report-run1415.md`（即 D4「不得覆盖」的落地）。这是**一次性回填**，**不是**新的命名规范 —— 常态命名仍是 `<日期>-round-<N>.md` / `<日期>-report.md` |
| **D6** | **授权同步（本 ADR 的实施面）**：章程 §11.3（轮次编号改取 `main`）+ **新增 §11.12**「轮次产物的落地（先落地，再自删）」+ 章程头部版本 1.16 → **1.17** + §12 变更历史一行；手册 §4.1.b（补「先落地，再自删」）+ §4.1.c（固定块里的轮次编号改为取 `main`）+ 头部版本 1.13 → **1.14** + §9 变更历史一行；`docs/adr/README.md` 登记 0054 + 「下一个可用编号」0054 → **0055**；`docs/memory/decisions.md` 追加一条；同一 PR 内回填 TASK-206 的搁浅证据（卡片 §5 / `LEDGER.md` / PL-091 / pitfall / 轮次产物）并落地 **DRIFT-206-1 方案 A**（TASK-206 write scope 增列 `docs/storage-design.md`，**仅 §3.4**）；`PLAN.md` 当前状态块 / `README.md` 三处 / `plans/stage-1-pilots.md` 当前进度句 / `MEMORY.md` 规模表同步 |

## 考虑过的选项（至少 2 个，含被否理由）

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 只在手册 §4.1.b 补一句，不动章程 | ❌ 否决 | 章程文件头明文「变更门槛：修改本章程需 ADR」；而这两条改的是**章程规则本身**（§11.3 的编号口径、§11 的自删前置条件），不是手册配方细节。只改手册 = 让手册与章程继续互相矛盾 |
| 2 | 让 run 在自删前把留痕**直接提交到 `main`**（跳过 PR） | ❌ 否决 | 违反 ADR-0046 A6 的合并判据（CI 全绿 + `mergeable_state = clean` + base = `main`）；且 `main` 受保护，直推会被远端拒绝 |
| 3 | 轮次产物改用 `<运行日日期>-<run id>-round-N.md` 彻底避开撞号 | ❌ 否决（本次） | 与 §11.3 的既有命名及历史产物不一致，属**改名类**决策（先例 ADR-0051 走了独立 ADR + 全量改名）；本次只做**最小修正**（取数口径 + 禁止覆盖），命名不变 |
| 4 | 让 agent 在自删前自检「有没有未合并的留痕」 | ✅ 采纳（D1 / D2） | 与 §11.2 的「先放锁再自删」同构 —— 都是**自删的前置条件**；且可用「`git status` 干净 + 本轮未写 `docs/**` / `tasks/**` / `LEDGER.md`」机械判定 |

## 后果（正 / 负）

- **正**：① 自动化的留痕**必然**可被下一个会话看到，不再依赖某个本地分支是否恰好被 push；② 轮次文件不再互相覆盖，运行日的轮次计数可信；③ 与「`next_run_at` 在 run 启动前就被清空」的既有风险口径一致 —— 失败的 run 仍会留下条目（手册 §4.1.b）。
- **负**：① 每轮**多一次 PR 周期**（哪怕只写了 1 行 LEDGER）—— 这是**有意的**代价：留痕可见性 > 省一次 CI；② D2 的例外依赖 agent 自检工作区，存在**误判**可能 → 判据写成机械条件，并**默认从严**（不确定就按 D1 开 PR）。
