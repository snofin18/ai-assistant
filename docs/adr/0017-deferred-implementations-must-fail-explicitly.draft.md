# ADR-0017　未实现项必须显式登记并显式失败

状态：**Draft**（自动工作单 W4，待人类批准）　日期：2026-10-02　Supersedes：decisions.md `[ADR:待建 0017]`　Superseded by：—
关联：`xtask/src/deferred.rs`、`xtask/README.md`、`.github/workflows/ci.yml`、`docs/governance-ai-agent-execution.md`

## 背景（为什么现在要决定）

门禁工具如果尚未实现却返回成功，会制造比“没有门禁”更危险的虚假安全感：
调用方、CI 和审阅者都会把退出码 0 当成“检查通过”，而不是“检查不存在”。

项目选择把未实现能力做成显式的延期清单：命令可以被发现、会被调用，但必须失败并说明
归属卡号；卫生规则也要公开“已实现 / 未实现”数量。这样，缺口是可检索事实，而不是沉默默认值。

## 决策（一句话）

**任何未实现的 xtask 子命令或卫生规则都必须显式登记，并在执行时以非零退出码失败；
禁止用占位成功、空实现或隐藏命令伪装成已实现。**

决策细化：

| # | 内容 |
|---|---|
| **D1** | 未实现子命令执行时返回稳定非零退出码，并打印归属卡号或 ADR；不得返回 0。 |
| **D2** | `--list-deferred` 等清单必须能枚举未实现项，供人类与 agent 读取。 |
| **D3** | `hygiene` 每次运行都声明已实现 / 未实现规则数量，不把手写名单当作唯一事实源。 |
| **D4** | CI 对“未实现子命令仍然失败”的负向验证属于门禁体系的一部分。 |
| **D5** | 实现某项后，同一变更必须把它从延期清单移出，并更新对应测试与文档。 |

## 考虑过的选项（至少 2 个，含被否理由）

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| 1 | **显式失败 + 延期清单（本 ADR）** | ✅ 采纳 | 缺口可见、可测试、可追踪；不会把“未跑”伪装成“通过”。 |
| 2 | 未实现命令返回 0 并打印提示 | ❌ 否决 | CI 与调用方只看退出码时会误判成功，直接违反“无静默失败”。 |
| 3 | 直接不注册未实现命令 | ❌ 否决 | 命令缺失与命令未实现无法区分，审计时看不到完整缺口。 |
| 4 | 只靠人工清单记录 | ❌ 否决 | 人工清单会与代码脱节，且无法在 CI 中证明失败语义仍然存在。 |

## 影响（需要改的 spec / 代码 / 文档 / 任务卡）

- `xtask/src/deferred.rs`：延期命令与卫生规则清单。
- `xtask` 命令分发：未实现命令返回显式失败，帮助文本仍可发现该命令。
- `xtask/README.md`：说明退出码与延期清单。
- CI：保留“延期命令失败”的负向验证。
- 后续实现卡：实现后同步从延期清单移除，避免同一事实两处漂移。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 退出码被后续重构意外改回 0 | 对延期命令加负向测试；CI 执行真实命令并断言非零退出码。 |
| 延期清单漏掉新命令 | 命令登记与清单测试保持结构对应；新增未实现命令必须同时登记。 |
| 已实现项仍留在清单中 | 实现卡同步移除，并用清单数量或覆盖测试发现漂移。 |

## 验证方式（怎么知道这个决策是对的；何时应重新评估）

1. 任取未实现子命令执行时返回非零退出码，并打印归属信息。
2. `cargo run -p xtask -- --list-deferred` 能枚举延期项。
3. xtask 单元测试覆盖“未实现命令失败”与“实现后移出清单”。
4. CI 的延期命令负向验证保持绿。
5. **重新评估触发**：当全部 xtask 子命令和全部卫生规则都已实现时，延期清单可以为空，
   但“缺口不得伪装成功”的规则仍保留。
