# ADR-0089　无人值守轮次上限：由 §6 diff 预算派生，且人类会话重置

状态：Accepted　日期：2026-10-13　Supersedes：—　Superseded by：—
关联：ADR-0046（一次性任务）、ADR-0054（轮次编号取数 = `main` / 禁止覆盖）、ADR-0072（派生值指向 SSOT）、
ADR-0088（运行日边界 08:00）、章程 §6 / §11.1 / §11.3、
`docs/automations/codex-automations-operations.md` §4.1.c / §6、`docs/audits/automation-26-audit-2026-10-13.md` §3

## 背景

章程 §11.3 的停止闸门写死为「当 `N > 3`（运行日已做满 3 轮）→ 本次运行不写代码」，其中 `N` =
`main` 上 `docs/automations/<运行日日期>-round-*.md` 的文件数 + 1（ADR-0054 D3/D4）。这暴露两个问题：

1. **`N=3` 是派生量，却被写死。** §6 的硬约束是「每次运行总 diff ≤ 1200 行（人类半天可审阅完）」
   与「单卡 diff ≤ 400 行」。`1200 ÷ 400 = 3` —— 3 只是这对参数的算术结果，不是独立拍的数。
2. **闸门被套用到"有人类在场"的会话上。** §11 章首写明「本章程适用于 automation」；§0 说自动化要
   更严是因为「无人值守移除了唯一的实时纠偏机制：人类」。但 `N` 只看 round 文件数、**不区分产出者**，
   于是"一卡一轮、人工审阅后再手工放行"的人类会话也会把 `N` 顶到 >3 而被拦下 —— 而这正是今天
   （2026-10-13）人类驱动三轮后遇到的形态。人类会话**每张卡已当场审过**，"攒一批给人类审"的前提不存在。

## 决策（一句话）

`N` 改为**由 §6 派生**（`N = ⌊总 diff 预算 ÷ 单卡 diff 上限⌋`），且停止闸门**只约束无人值守 automation
运行**、计数**自最近一次人类会话以来**（人类会话把计数重置为 0）；同时把**每个无人值守批次总 diff**
预算由 1200 上调到 **2000** 行，使 `N = 2000 ÷ 400 = 5`。

细则：

1. **D1　`N` 为派生值**：`N = ⌊总 diff 预算 ÷ 单卡 diff 上限⌋`。现行参数 = `⌊2000 ÷ 400⌋ = **5**`。
   以后改 §6 任一数值，`N` 自动跟随（ADR-0072：派生值不得手抄）。
2. **D2　预算上调**：§6「每次运行总 diff」1200 → **2000** 行，口径改为"**每个无人值守批次**总 diff"，
   即"自最近一次人类会话以来累计"；措辞由"人类半天可审阅完"改为"人类可在一个工作日内审阅完"。
3. **D3　闸门作用域**：§11.3 的停止闸门**只约束无人值守 automation 运行**，计数量记作 `N_auto`；
   **人类在场的会话不受该闸门约束**（每卡已人工审阅 + 逐卡放行 + PR 合并门禁）。
4. **D4　变体 2（人类会话重置）**：`N_auto` = **自最近一次人类会话轮次以来** `机制=automation` 的轮次数；
   人类会话轮次把它**重置为 0**。当 `N_auto > N`（现行 `> 5`）→ 该 automation 运行只补/校阶段报告。
5. **D5　机制标记**：每个轮次文件必须标 `机制：automation（无人值守）` 或 `机制：human（人类会话）`；
   **历史文件不改**（ADR-0051 / 0052 历史只读）。轮次文件命名序号仍按运行日递增、防覆盖（ADR-0054 D4 不变）。

## 考虑过的选项（含被否理由）

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 只把写死的 3 改成写死的 5 | ❌ 否决 | 仍是手抄派生值，违背 ADR-0072；下次改预算又要同步改 N |
| 2 | 闸门仍按"每运行日全部 round 文件数"计 | ❌ 否决 | 不区分产出者，人类驱动的"一卡一审"被误伤（本次问题根因） |
| 3 | 变体 1：按"每运行日 automation 轮次"计 | ❌ 否决 | 人类会话在运行日中途介入后仍不重置，攒批语义不准 |
| 4 | **`N` 派生 + 变体 2（人类会话重置）+ 总 diff 2000** | ✅ 采纳 | `N` 自动跟随预算；闸门只针对"无人值守攒批"；人类会话重置让"批"回到"自上次人类介入以来的累计" |

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 人类会话不受闸门后无界推进 | 人类流程本就是"一卡一审 + 逐卡放行"，单卡 diff 仍 ≤400；§8 审阅流程与合并门禁不变 |
| `机制` 字段被漏写 → `N_auto` 计错 | 操作手册 §4.1.c 与轮次文件模板要求该字段；漏写时按下限从严（视作 automation）处理 |
| 上调到 2000 加大单批审阅负担 | 由人类显式裁决；`N` 与 diff 预算绑定，超预算即由 `N_auto > N` 触发停止 |

## 验证方式

1. `cargo run -p xtask -- adr-index` → 0 error（0089 登记表 ↔ 文件 ↔ `decisions.md` 一致、下一个可用编号 = 0090）。
2. `cargo run -p xtask -- hygiene / docscan / check-ledger / memory-counts / card-check / refscan` → 全 PASSED。
3. 现行正文扫描：`rg -n "1200 行|N > 3|≤3 轮" docs/automation-charter.md docs/automations/codex-automations-operations.md` 应无残留旧口径
   （历史 §12 行与 ADR-0089 背景除外）。
4. 语义复核：`N = ⌊2000/400⌋ = 5`；一份"人类会话 → 5 个 automation 轮次"的序列应允许第 5 个 automation 轮，第 6 个起只补报告。

**重新评估的触发条件**：若单卡 diff 上限或人类审阅吞吐再次变化，再评估总 diff 预算；`N` 自动跟随，无需另改。
