# ADR-0037　任务卡编号分配策略（防止未来 xtask ↔ stage-1 撞号）

状态：**Accepted**（2026-09-20）　日期：2026-09-20　Supersedes：—　Superseded by：—
关联：ADR-0031（任务卡一卡一文件）、ADR-0036（撞号解决）、`MEMORY.md` §1 「⑦ 待人类裁决」（撞号号段未完全分离）

## 背景

TASK-065（ADR-0036 实施）已消除 5 编号组 × 2 张 + 1 张 sub-suffix 的现状撞号（共 11 张 → 0 撞号）。但**未来** xtask 护栏升级继续扩张（如 TASK-015 升级重做 + 后续批次）= 仍会与 stage-1 占位卡的 051~058 号段撞号风险。

**现状盘点（2026-09-20）**：
- 001~010 = stage-0 已 Done（TASK-001 ~ TASK-010）
- 011 / 035 = stage-1 已迁正文的卡（protocol / notepad-adapter）
- 012~034 / 036~058 = stage-1 批次表占位（48 张 Ready）
- 059~064 = xtask 护栏升级（6 张 Done）
- 065~070 = 治理类卡（audit cleanup 批 6 张 Done）
- **072~099 = 空白**（XTASK 池）
- **100~199 = 空白**（新批次 / 跨阶段用）

**机器化保证**：xtask card-check 判据 ⑤「编号唯一性」尚未实现（PL-002 / ADR-0036 D5）= 未来 xtask 扩张仍会**手动**撞号风险。本 ADR 把号段分配规则写死 + xtask 卡号来源改成「**XTASK 池 072~099 自动取**」= 半机械化（人类仍需选号，但选号空间不撞）。

## 决策

**D1. 三号段分配**：

| 号段 | 用途 | 备注 |
|---|---|---|
| **001~099** | 已用 + xtask 池（072~099 空白）| xtask 护栏升级未来卡用 072~099 |
| **100~199** | 新批次 / 跨阶段用 | stage-2 / stage-3 / stage-4 未来卡使用 |
| **200~299** | 治理类批（audit / docs / memory 治理）| 与 xtask 完全分离 |

**D2. xtask 卡号池**：072~099（共 28 个号）= 当前 059~070 已用 12 个 + 未来 16 个空位。
- 当 072~099 用满时，**xtask 卡必须用 200~299 治理池**（不再向 100~199 业务池渗透）

**D3. 跨号段迁移规则**：任何卡需要**主动改号** = 必须开 DRIFT-ADR 引用本 ADR（与 ADR-0036 / 0031 D7 同级别严控）。

**D4. xtask card-check 判据 ⑤ 实现要求**：xtask card-check 实现时，编号唯一性检查必须**校验号段**（= 不允许 059~070 与 072~099 跨段撞号 + 任意 NNN > 100 时单独检查段内唯一性）。本 ADR 不实现 xtask 代码，仅约束**未来实现**该怎么用。

**D5. sub-suffix 命名彻底禁用**：`TASK-NNNx` / `TASK-NNNa` / `TASK-NNNb` 等**永久禁用**（= ADR-0031 D7 + ADR-0036 D3 强化）。任何命名违规直接报错。

## 不接受的反模式

1. **不**让 xtask 卡占用 100~199 业务池：xtask 是「事后插入的护栏工作」，与业务工作主题不同，必须用专门池。
2. **不**让 stage-1 卡占用 072~099 XTASK 池：stage-1 是已就位 48 张批次表，迁移代价大。
3. **不**恢复 sub-suffix 命名：NNNb 等已撞号事故（ADR-0036 §1）。
4. **不**让 governance 卡（200~299）混入 xtask 池：audit 治理与 xtask 护栏是**两种不同治理**。
