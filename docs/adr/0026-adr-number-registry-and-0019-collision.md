## 背景（为什么现在要决定）

项目的决策有**两个落点，共用一套编号**：

1. `docs/memory/decisions.md` 的 `[ADR:待建 NNNN]` 条目 —— 决定已做，正式 ADR 文件未写；
2. `docs/adr/NNNN-*.md` 文件 —— gov §9.3 模板的完整 ADR。

2026-09-16 一次性预留了 **0001~0020** 共二十个号（全部只落 ①）。2026-09-17 起开始建 ②，
但建文件时**没有回查预留表**，于是产生两个问题。

### 问题 A：0019 号被两条不同的决策占用

| 占用方 | 决策内容 | 时间 |
|---|---|---|
| `decisions.md` 的 `[ADR:待建 0019]` | `#[allow]` 的唯一合法位置是 `#[cfg(test)] mod tests` 上的 `clippy::unwrap_used` / `expect_used` / `panic` | 2026-09-16 预留 |
| `docs/adr/0019-hard-gate-negative-verification.md` | 硬门禁必须配「负向验证」（元门禁） | 2026-09-17 建文件 |

对照 0018 可以看出正确做法长什么样：0018 的预留主题（夜间自动化用 heartbeat）与文件主题
（夜间自动化的投递机制）**是同一件事**，且文件头显式写了
`Supersedes：MEMORY.md §3 [ADR:待建 0018]` —— 取代链完整、无歧义。
0019 的文件头是 `Supersedes：—`，**取代链断裂**，两条决策就这样静默共号。

### 问题 B：章程 §13 W4 的 write scope 已过期

W4 要在夜间产出 `docs/adr/0016-*.draft.md ~ 0020-*.draft.md`（5 个新文件），但
0018 / 0019 已有同号 Accepted 文件 → 真跑起来会产生**同号双文件**；
W4 的「禁止」项还写着「新建 0021 及以后的编号」，恰好封死了本 ADR 需要的改号动作。

### 为什么现在必须定

夜间自动化一旦通过验收（`docs/memory/open.md` **N4**）开始真跑，W4 会在**无人值守**下
制造同号文件；而「编号」是 ADR 体系的主键，主键重复会让后续所有 `Supersedes` /
`Superseded by` 链条失真。这是典型的「越晚修越贵」。

## 决策（一句话）

**建立 `docs/adr/README.md` 作为 ADR 编号的唯一登记表（新建前必查、新建后必回填），
并把 `[ADR:待建 0019]`（`#[allow]` 位置那条）改号为 `[ADR:待建 0027]`，
0019 归 `hard-gate-negative-verification` 独占。**

拆成四条：

- **D1　登记表**：新建 `docs/adr/README.md`，含 ①已存在文件表 ②待建号表
  ③已知事故 ④引用规范。它是**描述性**文档（只陈述事实），本身不含决策；
  「号的分配」变更仍须走 ADR。
- **D2　改号**：`#[allow]` 那条决策的待建号 **0019 → 0027**。在 `decisions.md`
  以**追加**方式写一条 `[ADR:待建 0027][supersedes: 2026-09-16 的 [ADR:待建 0019] 条目]`，
  原条目**不改写**（遵守 `decisions.md`「只追加，不改写他人条目」的规矩）。
- **D3　引用规范**：引用「未建文件」的决策一律写 `[ADR:待建 NNNN]`，**禁止裸写 `ADR-NNNN`**；
  ADR 文件若取代某个待建条目，`Supersedes` 行**必须**写明 `decisions.md [ADR:待建 NNNN]`
  （不得留 `—`）。
- **D4　章程 W4 修正**：W4 的 write scope 改为 **0016 / 0017 / 0020 / 0027** 四个号
  （0018、0019 已有文件，剔除），「禁止」项改为「新建 0028 及以后的编号」，
  验收里的「5 个文件」相应改为「4 个文件」。章程版本 1.3 → **1.4**，§12 变更历史追加一行。

## 考虑过的选项

| # | 方案 | 结论 | 理由 |
|---|---|---|---|
| 1 | 把 `0019-hard-gate-*.md` 改名为 0027，待建 0019 保持原号 | ❌ 否决 | 0019 文件已被**十余个文件**引用（`LEDGER.md`、gov、`DEPENDENCIES.md`、`SPIKE-A.md`、ADR-0023/0024/0025、`plans/stage-0-spikes.md`、`tasks/TASK-001-*`…）；改号要同步全部引用并破坏既有 git 历史的可读性。改一个**尚未落地的预留号**代价接近零 |
| 2 | 不改号，只在 README 注明「0019 有两个含义」 | ❌ 否决 | 主键允许重复 = 没有主键。以后任何 `Supersedes: ADR-0019` 都永久有歧义，且夜间自动化会自动踩上去 |
| 3 | 待建号与文件号**分成两套编号空间**（如待建改用 `PEND-NNNN`） | ❌ 否决 | 两套号终究要在「待建转正」那一刻对齐，对齐点就是今天的冲突现场，等于把问题推迟而不是解决；且 `decisions.md` 已有 20 条 `[ADR:待建 NNNN]`，全量改标签是纯成本 |
| 4 | 只记 PARKING_LOT，什么都不动 | ❌ 否决 | PL 的语义是「不相关但值得记住」；本问题是**当前文档体系的完整性缺陷**，且会随夜间自动化上线**自动恶化**，不符合「停到阶段末再评审」的门槛 |
| 5 | 本 ADR + 登记表 + 改号（选定方案） | ✅ 采纳 | 一次性把「号从哪来、谁占了、怎么引用」定死；登记表还带**预防**作用（新建前必查），不只是事后补救 |

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 人类否决改号 → 已建的 README 与本 ADR 反而成了误导 | 本次全部改动集中在**一个提交**，`git revert` 一次即可；本 ADR 状态明写 `Proposed`，README §3 也明写「ADR-0026 被确认前不要为 `#[allow]` 那条建文件」 |
| 登记表与真实文件再次脱节（表说没有、其实有） | 登记表目前是**手工维护** → 记 **PL-030**：建议给 `xtask` 加 `adr-index` 子命令（扫 `docs/adr/*.md` 的号 ↔ README 表格，不一致即失败），归 TASK-015。**本次不实现**（加子命令是漂移触发器 ②，且不在任何卡的 write scope） |
| 0027 在确认前被别的决策抢用 | README §1 已标注「下一个可用编号：0027 —— 已预留给 `#[allow]` 决策（ADR-0026 D2，Proposed）」 |
| 裸引用（PL-028 那 2 处）继续被照抄扩散 | D3 的引用规范已写进 README §4 的对照表；`xtask check-comments` 未来可加一条规则：**裸写 `ADR-00NN`（NN 属 §2 的待建号集合）且出现在 `docs/adr/` 之外 → Warning**。该规则的正则含竖线字符，直接写进 Markdown 表格会破表（见 PL-031），故此处只描述语义、实现时再落到代码，归 PL-030 一并考虑 |

   无 setext 标题风险（`---` 前必须空行）。
