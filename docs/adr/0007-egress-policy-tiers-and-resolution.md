# ADR-0007　出域策略三档、覆盖优先级与 endpoint 白名单

Supersedes：decisions.md `[ADR:待建 0007]`　Superseded by：—

`tasks/TASK-050-dlp-three-tier-egress-local-only-redacted-full.md`、`crates/dlp/**`

## 背景

架构 v2 已确定出域策略由用户选择三档 `local_only` / `redacted` / `full`，
支持全局默认、逐应用覆盖与逐内容类型覆盖，并要求默认拒绝未配置的 endpoint。
但现有文档没有冻结两处实现必需但容易产生不同解释的细节：

1. 全局、逐应用与逐内容类型同时命中时，哪一个级别生效；
2. `local_only` 与 endpoint 白名单、策略变更审计之间的职责边界。

如果不先冻结，`crates/dlp` 的实现只能猜优先级，且“更宽松的覆盖能否压过更严格的默认”
会成为静默绕过路径。TASK-050 已作为 Ready 卡认领实现，本 ADR 只冻结该实现所需的纯逻辑契约。

## 决策（一句话）

**出域级别按严格度 `local_only > redacted > full` 解析；逐应用覆盖替换全局默认，逐内容类型
覆盖只能在应用结果上继续收紧；选 `local_only` 而无本地模型时显式失败，非本地出域必须命中
endpoint 白名单；DLP 产生可审计的变更记录，但不自行写审计存储。**

## 决策细化

| # | 内容 |
|---|---|
| **D1** | `EgressLevel` 的严格度顺序固定为 `LocalOnly` > `Redacted` > `Full`；`is_wider_than` 只用于判断“是否扩大出域”，不得改变该顺序。 |
| **D2** | 先取基线级别：命中逐应用覆盖时用它替换全局默认，否则用全局默认。若命中逐内容类型覆盖，则有效级别 = `strictest(基线, 内容类型覆盖)`；因此应用覆盖可以按用户显式选择放宽或收紧默认档，而内容类型覆盖不能让更严格的应用结果变宽。实现不得采用“最后命中覆盖”或未文档化的字段优先级。 |
| **D3** | 有效级别为 `LocalOnly` 时，调用方必须显式提供“本地模型可用”；不可用返回 `LocalModelUnavailable`，绝不降级到 `redacted` / `full`，也不尝试云端。 |
| **D4** | 有效级别为 `Redacted` / `Full` 时，请求 endpoint 必须存在于策略的白名单中；空白名单、未知 endpoint、非法 endpoint 标识一律显式失败。`LocalOnly` 不检查 endpoint 白名单，因为该路径不允许出域。 |
| **D5** | `Redacted` 决策必须携带 `redaction_required = true`；DLP 只返回要求，不在本 crate 内读取文本、截图或像素，也不执行正则匹配。 |
| **D6** | 级别变更若扩大出域范围（例如 `LocalOnly` → `Redacted` 或 `Redacted` → `Full`），变更记录必须标记 `requires_upgrade_confirmation = true`，供 UI/宿主执行“升级需显式说明”。DLP 不实现 UI 或审批。 |
| **D7** | 修改默认级别、应用覆盖或内容类型覆盖时返回不可变的 `EgressPolicyChange`；宿主负责把该记录落审计。`crates/dlp` 不依赖 audit/storage，不做 IO、时钟或全局状态。 |
| **D8** | 所有长期集合必须有硬上限：应用覆盖 ≤ 128、内容类型覆盖按封闭枚举自然有界、endpoint 白名单 ≤ 128；超限、重复键、空或非法标识均拒绝。 |
| **D9** | 本 ADR 不新增第三方依赖、不改 `protocol/**`、不改公共 trait / IPC / `ErrorCode`；新增面仅限 `crates/dlp` 的纯 Rust 类型与函数。 |
| **D10** | 架构 v2 中“正则/词典命中”的执行方仍是调用方或文本扫描层；DLP 只消费已判定结果，遵守 ADR-0073 对 regex 依赖的否决。 |

## 考虑过的选项（至少 2 个，含被否理由）

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 覆盖优先级固定为“内容类型 > 应用 > 全局”，允许内容类型无条件替换 | ❌ 否决 | `screenshot=full` 会放宽 `stock=local_only`，与“截图默认更严”和敏感应用默认不出域的安全意图冲突。 |
| 2 | 取全局默认、应用覆盖、内容类型覆盖三者的最严格者 | ❌ 否决 | 会使架构 §12.6.1 的“默认 `redacted` + Notepad `full`”永远失效；逐应用覆盖失去用户显式覆盖的能力。 |
| 3 | **应用覆盖替换默认，内容类型覆盖再取严格者** | ✅ 采纳 | 保留逐应用显式选择的能力，同时让截图/剪贴板等内容类型规则只能加严，不能绕过更严格的应用设置。 |
| 4 | `local_only` 无本地模型时自动降级到 `redacted` | ❌ 否决 | 直接违反架构 v2 §12.6.1 的“降级不静默”，也会把本地敏感内容意外交给云端路径。 |
| 5 | DLP 直接依赖 audit/storage 并落策略变更审计 | ❌ 否决 | 违反 ADR-0071 的 crate 边界，并把纯策略判定与持久化事务耦合；改为返回 `EgressPolicyChange`，由宿主在已装配的审计链中落库。 |

## 影响

- TASK-050 在 `crates/dlp/**` 内实现三档解析、逐应用/逐内容类型覆盖、endpoint 白名单与
  `local_only` fail-closed；无需新增依赖或修改既有公共契约。
- UI 与宿主仍持有最终放行链：初始向导、升级说明、审批、策略持久化和审计写入不在本 ADR 内。
- `docs/memory/decisions.md` 的 `[ADR:待建 0007]` 由此毕业为完整 ADR；原历史条目保留，不回溯改写。
- `docs/adr/README.md` 把 0007 从待建表移入已存在文件表；下一个可用编号不变。

## 验证方式

1. 正向他：应用覆盖可替换默认；内容类型覆盖可收紧应用结果但不能放宽它。
2. 负向他：`local_only` 无本地模型 / endpoint 不在白名单 / 重复键 / 超上限 / 空标识均显式失败。
3. 升级检测：`LocalOnly` → `Redacted`、`Redacted` → `Full` 被标记为需要显式确认；
   同级和收窄变更不得误报。
4. 边界：应用覆盖 128 条、endpoint 128 条可通过；129 条拒绝且原因稳定。
5. 纯函数：同一策略与请求重复求值得到同一决策；测试不依赖 IO、时钟、网络或 GUI。

## 重新评估触发条件

- 若 UI 或产品要求“用户明确选择的更宽覆盖必须压过更严格默认”，必须先改本 ADR 并补升级说明路径；
- 若本地模型生命周期需要把“可用”改为更细的探测结果，扩展输入类型前先补 ADR；
- 若 endpoint 白名单需要 URL 路径级语义或网络解析，按新依赖 ADR 处理，不在 DLP 纯逻辑内扩展。
