# ADR-0050　自动化规则时间中性化 + 默认间隔 2 h + 开始时刻互斥

## 背景（为什么现在要决定）

1. **「夜间」是历史命名，不是机制限制**：automation 机制本身**没有**任何「只在夜间」的约束；ADR-0046 A4 也已写明「自动化在每天任何时候都可以提出」。但章程 / 手册 / README 的措辞仍大量使用「夜间 / 当夜 / 晨间报告」，会让读的人（尤其开源后的外部读者）以为自动化只能在夜里跑。
2. **默认 3 h 与实测不符**：ADR-0049 依据 7 个一次性 run 的一手时长（最长 64.1 分钟）把**下限**降到 2 h，但**默认**仍留 3 h。人类要求默认也改为 **2 h**。
3. **「同一时刻两个」是真实风险**：`executionEnvironment = "local"` 时多个 automation 共用**同一个主 checkout**；若两个的开始时刻相同，会同时改同一工作树，产生无法归因的混合改动。ADR-0046 D3 只写了「间隔 ≥ X」，**没有**把「开始时刻不得相同」写成硬规则。

## 决策（一句话）

**自动化规则时间中性化**（文中「夜间 / 当夜 / 晨间」一律降为历史命名：「当夜」= **运行日**、「晨间报告」= **阶段报告**）；
**不同自动化之间的间隔 ≥ 2 小时且默认也是 2 小时**；
**同时存在 ≥ 2 个 automation 时，其（计划）开始时刻必须互斥 —— 严禁两个在同一时刻开始 / 同时运行。**

## 决策细化

| # | 内容 |
|---|---|
| **D1** | **时间中性**：automation 可在**每天任何时间**运行。章程 / 手册的**规范文字**不再把「夜间」当作适用前提；「当夜」的正式名称改为 **运行日**（§11.3）、「晨间报告」改为 **阶段报告**（§11.4）。**历史命名保留但显式标注**：文件路径 `docs/overnight-automation-charter.md`、目录 `docs/nightly/`、锁名 `.nightly.lock` 与 `nightly/<date>` 分支名**本次不改**（全量改名 = 另案，见 D5 / PL-089）。 |
| **D2** | **间隔 = ≥ 2 h，默认 2 h**：ADR-0046 D3 的**默认值**由 3 h 改为 **2 h**；ADR-0049 D1 的**下限** 2 h 不变（本 ADR 只改默认，不改下限）。 |
| **D3** | **开始时刻互斥（新增硬规则）**：只要**同时存在 ≥ 2 个** automation，它们的**（计划）开始时刻必须互斥** —— 严禁两个在同一时刻开始、严禁两个同时运行。人类给时刻时 agent **必须**核对并提示冲突；`间隔 ≥ 2 h` 是这条规则在**时间维度**的落地。 |
| **D4** | **锁仍是必需的第二重保护**：`.nightly.lock`（章程 §11.2 / G8）继续有效，**不因**「开始时刻互斥」而取消 —— 间隔/互斥是**概率 + 计划层**的保护，锁是**运行时判据**（ADR-0028 / ADR-0046 D3 的原话）。 |
| **D5** | **授权修订**：`docs/overnight-automation-charter.md` §11.1（现状行 + 排期形态段）/ §11.2（措辞）/ §11.3（标题 + 运行日）/ §11.4（标题 + 阶段报告）/ §11.9 / §11.11 A2，`docs/nightly/codex-automations-operations.md` §4.1 / §4.1.a / §4.1.c / §6；两文件各升一版。**不授权**：文件 / 目录 / 锁名 / 分支名的改名（`docs/overnight-automation-charter.md` → `docs/automation-charter.md`、`docs/nightly/` → `docs/automations/`、`.nightly.lock` → `.automation.lock`、`nightly/<date>` → `automation/<date>`）—— 该改名要动 `README.md` 的**冻结段**（ADR-0039 D5 的例外）与只追加的记忆条目，**另案裁决**（PL-089）。 |
| **D6** | **不改** ADR-0046 的 D1（建立需人类指令）/ D2（一次性）/ D4（内容按实际进度）/ D6~D8（授权与升级协议）。**「跑完自动链式续建下一个」仍属未授权**（ADR-0046 选项 4 曾否决）—— 人类的**有界计数器链**提案见 PL-088，**待裁决**。 |

## 考虑过的选项（至少 2 个，含被否理由）

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 保持「夜间」措辞 + 默认 3 h | ❌ 否决 | 与机制事实（任何时间可跑）不符；默认 3 h 与 7 次实测（最长 64.1 min）相比过度保守 |
| 2 | **时间中性化 + 默认 2 h + 开始时刻互斥**（本 ADR） | ✅ **采纳** | 措辞与机制一致；2 h 有实测支撑；互斥把「同时运行」从「概率」提升为「计划层硬规则」 |
| 3 | 一次到位把文件 / 目录 / 锁名 / 分支名全部改名 | ❌ **本次否决（不否决其必要性）** | 要动 `README.md` 冻结段 + 只追加的记忆条目 + 大量只读历史记录（LEDGER / 任务卡记录 / ADR 正文）；**另案**（PL-089） |
| 4 | 取消最小间隔，只靠开始时刻互斥 + `.nightly.lock` | ❌ 否决 | 锁是**协作式**、无法技术强制（ADR-0028）；互斥只约束**计划时刻**，不能约束**实际时长** |

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 「开始时刻互斥」被误读成「已取消锁」 | D4 明确锁仍是必需判据；章程 §11.2 一字不改其锁规则 |
| 默认降到 2 h 后两轮真的重叠 | D3 的计划层互斥 + D4 的运行时锁；任一新 run > 2 h → 回 ADR-0049 重开（ADR-0049 D5） |
| 时间中性化被当成「已全量改名」 | D1 明确路径 / 目录 / 锁名 / 分支名**本次不改**，并在两文件头部写「历史命名」声明；全量改名见 PL-089 |
| 有人把 PL-088 的链式提案当成已授权 | D6 明确「链式续建仍属未授权」；PL-088 状态 = 待裁决 |

## 验证方式（怎么知道这个决策是对的；何时应重新评估）

1. 下一次建 automation 时核对：人类给的时刻**两两不同**且间隔 ≥ 2 h（D2 / D3）；
2. 章程 / 手册的**规范文字**里不再有「只在夜间」的表述（D1）；
3. **何时重新评估**：出现两个 run 真的重叠，或全量改名（PL-089）落地后需回填本 ADR 的 D1。
