# ADR-0063　资源生命周期纪律：长期状态必须有界，子进程必须回收

状态：**Accepted**（2026-10-02 人类「记入项目必须遵守的操作规则」）
日期：2026-10-02
Supersedes：—
Superseded by：—
关联：**TASK-220**、**TASK-221**、ADR-0028、ADR-0062、`AGENTS.md` §12、`docs/memory/pitfalls.md`

---

## 背景

两轮泄露审计（TASK-220 / TASK-221）实测确认了四类会在长期运行中耗尽资源的缺陷：

1. Windows UIA 元素表只增不删，持续累积 COM 引用；
2. 生产根 anchor 注册表与审批授权表随任务数无界增长；
3. `CostLedger.records` 是追加型无界集合；
4. PowerShell 靶机在启动失败路径既不 kill 也不 reap，留下孤儿进程。

这些都不是"某一次调用写错"，而是**每新增一个有状态组件或子进程时都可能复发**的结构性问题。
只修这一次不够，必须把"资源生命周期"提升为全项目操作规则。

## 决策（一句话）

**任何长期驻留状态必须有硬上限与显式淘汰/拒绝；任何子进程必须有明确的终止 + reap 路径
（含失败路径）；任何新增有状态组件或子进程的卡必须在 DoD 里附泄露证据。**

## 决策细化

| # | 内容 |
|---|---|
| **D1 长期状态必须有界** | 任何会随任务/请求/时间增长的 `Vec` / `BTreeMap` / `HashMap` / 队列，必须有硬上限与淘汰或拒绝策略。无界累积不得进入主分支。 |
| **D2 淘汰必须可测且不撒谎** | 淘汰策略要有单测；聚合量（如成本总计、计数）不得因历史淘汰而失真；淘汰后对失效项的引用必须显式失败（`TargetNotFound` / 错误码），不得静默给错值。 |
| **D3 子进程必须终止 + reap** | 启动的子进程必须有 `Drop`/失败路径的终止逻辑，并覆盖**进程树**（如 Windows `taskkill /T /F`）；终止后必须 `wait()` reap，绝不留孤儿或僵尸。 |
| **D4 失败路径同等对待** | "启动后做就绪探测/握手，探测失败"这类分支必须在返回错误前终止并 reap 子进程，不能只依赖调用方的 Drop。 |
| **D5 线程本地资源要能释放** | 线程本地的 COM/句柄/缓存表必须有上限或显式清理入口，不能假设"线程会退出所以不用管"。 |
| **D6 新卡必须附泄露证据** | 新增有状态组件或子进程的任务卡，DoD 必须包含：上限/淘汰单测、真实运行后资源收敛证据（进程数/句柄/工作集），或对"为何不会增长"的明确论证。 |
| **D7 审计结论要留档** | 每轮泄露审计必须记录"修了什么"和"复查过、无问题"的子系统清单，避免下轮重复劳动；改动落 `LEDGER.md` 与任务卡。 |
| **D8 不改公共契约** | 本规则不要求改 trait / 协议 / schema；实现一律落在既有模块内。需要改公共形状时另立 ADR。 |

## 被否决的选项

| 选项 | 结论 | 理由 |
|---|---|---|
| 只修本轮发现的点，不立规则 | ❌ | 结构性问题会随新组件复发；这正是两轮审计的教训。 |
| 给所有集合加一个统一"全局 LRU 框架" | ❌ | 引入新抽象层与依赖；多数集合的淘汰语义不同，统一框架会掩盖"这个必须 fail-closed"的差别。 |
| 靠"记得写清理" | ❌ | 与 ADR-0030 的动机一致：靠记忆的护栏已证明会失效。 |
| 把子进程清理只放在 Drop | ❌ | Drop 不覆盖"返回错误前"的分支；TASK-220 的 PowerShell 遗留就是实例。 |

## 影响

- `AGENTS.md` 新增 §12「资源生命周期」并把它列为必守操作规则。
- 后续任务卡模板的 DoD 增加"资源泄露证据"一项（对触及长期状态/子进程的卡强制）。
- TASK-220 / TASK-221 的修复成为本规则的参考实现。
- `docs/memory/pitfalls.md` 记录两条通用坑：元素表/注册表无界、子进程失败路径不 reap。

## 验证方式

1. `AGENTS.md` §12 落地后，新卡模板与本 ADR 一致。
2. 下一次新增有状态组件的卡，其 DoD 含上限单测与收敛证据。
3. 第三轮泄露审计（真机长跑）验证 TASK-220/221 的上限在真实负载下确实收敛。
