# ADR-0046　自主自动化的形态：人类指令驱动的「一次性」任务

状态：**Accepted**（2026-09-25，人类 chat 给出完整 7 条规格）　日期：2026-09-25　Supersedes：—　Superseded by：—
关联：`docs/overnight-automation-charter.md` §11（本 ADR 授权修订 §11.1 / §11.3 / §11.4 并新增 §11.11）、`docs/nightly/codex-automations-operations.md` §4.1、`docs/PARKING_LOT.md` PL-077、ADR-0029（机制）、ADR-0028（guard 锁）、ADR-0041（计划文件可写面）

## 背景（为什么现在要决定）

2026-09-25 本 agent 在**同一天内两次建错** automation：

1. 先按章程 §11.1/§11.3 的「每夜两次」建了**常驻** cron（还自行把频率降为一次/日，登记为 PL-076）；
2. 被人类指出「自动化只跑了 019，之后没有」后，又补建第二个**常驻** cron 凑成「两次」。

两次都**方向性错误**：人类要的不是「常驻排期」，而是「**下指令、当场建一次性任务**」。
两个 automation 已按人类指示全部删除（磁盘复核：`~/.codex/automations/` 回到只剩 `.run-jitter-salt` 的基线）。

**根因**：把章程 §11.1/§11.3 的**既有设计当成需求**直接落地，**没有先确认「人类希望怎么建」**。
这是 gov §0.1「上下文污染 + 想当然」的教科书案例，故本节保留为反例。

人类随后给出**完整 7 条规格**，本 ADR 将其固化为唯一事实源。

## 决策（一句话）

**自主自动化 = 由人类指令触发的「一次性」任务**：每次由人类下指令时建立；**每个不同自动化之间的间隔至少 2.5 小时（默认 3 小时）**；
**任务内容按实际进度现场决定**（prompt 不写死卡号）；人类可在**任何时间**提出；
执行中默认授权 agent 按**最优解**自决（前提 = 遵守规则）并**授权 git 合并**；
遇到**无法决定 / 没有最优解 / 重大错误无法解决**时：**可跳过则跳过并继续，不可跳过则停止、返回失败、告知详情**。

## 决策细化

| # | 内容 |
|---|---|
| **D1** | **建立的前提 = 人类指令。** 任何 automation 的创建（**含探针 / 验证用**）都必须先有人类指令；agent **不得**自行创建、也不得「跑完自动再建下一个」链式续建。→ 直接后果：手册 §4.1 的「一次性任务怎么建」在**下一次有人类指令之前无法实测**，状态保持 `[未验证]`（子块 = `#### 4.1.a`） |
| **D2** | **一次性** = 触发一次即完成，**不做**每日 / 每周重复。具体写法（RRULE 的 `COUNT=1` / `UNTIL`，或工具另有一次性语义）目前 `[未验证]` —— 必须在下一次建立时**当场实测**（含「第二次触发不发生」的观察）并把结论回填手册 **§4.1.a** |
| **D3** | **间隔 ≥ 2.5 小时（默认 3 小时）**：指**不同自动化之间**的计划时刻间隔。理由 = 杜绝两个同时运行（`executionEnvironment = "local"` 时多轮共用同一个主 checkout 工作树）。这是对章程 §11.2 / G8 互斥锁的**时间维度**补充；锁仍是必需的**第二重**保护，不因间隔而取消 |
| **D4** | **任务内容按实际进度决定**：prompt **不得**写死具体卡号清单。每轮先读 `PLAN.md` 的「当前状态」块 / `plans/<阶段>.md` 头部进度句 / `tasks/` 状态行 / `LEDGER.md` 末 10 行，**由实际进度推出**本轮该做什么；agent **也可以提出建议**，发现安排有错时**可以提出** |
| **D5** | **任何时间可提**：不限于夜间。章程的「当夜」概念（§11.3）继续用于**产物命名与轮次计数**，但**不再**约束建立时刻；原「计划时刻距 00:00 至少 10 分钟」由**硬规定降级为建议**（抖动仍会把贴近日界的触发推过日界） |
| **D6** | **默认授权（按最优解自决）**：执行中命中的漂移由 agent 自决，**前提 = 遵守规则**（仍不得放宽 lint / 改测试断言 / 越过铁律）；裁决**必须落盘**（卡 §5 + `LEDGER.md`，必要时 `docs/memory/{facts,pitfalls,rejected}.md`）。**只在聊天里说过的决定视为未发生** |
| **D7** | **授权 git 合并**：同时满足「CI 全部 check = success」+「`mergeable_state = clean`」+「base = `main`」时，agent 可自行合并自己的 PR；任一不满足则只开 PR、不合并，并把原因写进当轮报告 |
| **D8** | **升级协议（含人类点 7）**：遇到**无法决定 / 没有最优解 / 重大错误无法解决**时 —— ① **先记录**（`docs/PARKING_LOT.md` 一行 + `LEDGER.md` 一行；重大者写进卡 §5 或 §7）；② **可跳过 → 跳过该子项并继续**本轮剩余工作；③ **不可跳过 → 停止、返回失败、告知详情**（现象 / 影响 / 已尝试 / 建议 / 已停工作）。**禁止**把「无法决定」伪装成「已完成」（铁律 1） |
| **D9** | 本 ADR **授权修订**：`docs/overnight-automation-charter.md` 的 §11.1（现状行）/ §11.3（排期口径）/ §11.4（谁写报告）/ **新增 §11.11（本 ADR 7 条 + 升级协议）**，以及 `docs/nightly/codex-automations-operations.md` §4.1（一次性建法 + 建立前必须有人类指令）。**派生同步（否则同一事实在两份文档里互相矛盾 = 漂移触发器 ⑧）**：章程 §11.9 的「当前状态」段落（属状态字段，另有 ADR-0041 D5 授权）＋手册 §6 映射表的表头版本行与第 1 / 12 行（这两行**逐字引用** §11.1 与 §11.3 被改写的口径）。先例 = ADR-0041 D5 / ADR-0045 D5 |
| **D10** | **不与既有决策冲突的部分**：ADR-0029 的**机制结论**（主方案 = Codex 原生 scheduled tasks、standalone / cron 类）与 ADR-0028 的锁协议**继续有效**，本 ADR 只改「**排期形态**」（常驻 → 人类指令驱动的一次性） |

## 考虑过的选项（至少 2 个，含被否理由）

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 常驻每日 cron（2026-09-25 实测过两次） | ❌ **否决，已删除** | 任务内容被 prompt 写死 → 永远只跑同一批卡；无法按实际进度决定下一步；人类也无法在白天按需调整 |
| 2 | 常驻 + 每天人工改 prompt 更新卡号 | ❌ 否决 | 等于每次都要人类再下一次指令，却额外背上「常驻任务在无人下指令时自己跑」的风险 |
| 3 | **人类指令驱动的一次性任务（本 ADR）** | ✅ **采纳** | 人类每次都能决定「现在做什么、几点做」；agent 仍按实际进度推导具体内容；间隔 2.5~3 h + 互斥锁 = 双层并发保护 |
| 4 | 一次性，但由 agent 跑完自动链式续建下一个 | ❌ 否决 | 违反 D1；且会退化成**事实上的常驻**，把人类重新排除在决策之外 |

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 「一次性」写法未验证 → 建出来其实会重复触发 | D2 明确 `[未验证]`；下一次建立时**当场**用磁盘核对 + 「第二次触发不发生」的观察验证；验证前不把「一次性」当既成事实（铁律 1） |
| 间隔 2.5 h 仍可能重叠（某轮超过 2.5 h） | 章程 §11.2 / G8 的 `.nightly.lock` 仍是**必需项**：间隔只降低概率，**锁才是判据** |
| agent 再次「想当然」把章程某段当需求 | D1（建立需人类指令）+ D4（内容按实际进度推导）都强制**先读现状再动作**；本文「背景」节保留本次事故作为反例 |
| 无法决定时被静默糊过去 | D8 明确「记录 + 跳过或停止返回失败」，禁止伪装完成 |

## 验证方式（怎么知道这个决策是对的；何时应重新评估）

1. **下一次人类下指令建立时**：核对 `~/.codex/automations/<id>/automation.toml` 的 `rrule` 是否**确为一次性**语义，并观察**第二次触发不发生**；结论回填手册 **§4.1.a**（对应 D2）；
2. 「间隔 ≥ 2.5 h」在人类给出的多个时刻上核对（D3）；
3. 「任务内容按实际进度」在**下一轮运行报告**里核对：报告必须写清「本轮为什么做这件事」及其依据文件（D4）；
4. **何时重新评估**：若出现「一次性任务实际重复触发」或「两轮真的重叠」→ 回到本 ADR 重开（改决策 = 新 ADR）。
