# ADR-0083　任务卡状态行：正文区的唯一可写例外

状态：**Accepted**（2026-10-07，预授权自动化轮次代为裁决）　日期：2026-10-07　Supersedes：—　Superseded by：—
关联：ADR-0031（一卡一文件）、ADR-0041（计划文件可写面）、`AGENTS.md` §8、`docs/governance-ai-agent-execution.md` §3.2~§3.4、`PL-073`

## 背景（为什么现在要决定）

ADR-0031 D2 把任务卡状态唯一落点定为卡片文件的 `- 状态：` 行，并要求 Implementer
在任务状态变化时更新它；但同一 ADR 又规定分界线以上的“正文区”只读，而状态行物理上位于
分界线以上。`docs/PARKING_LOT.md` 的 `PL-073` 记录了这个矛盾：

- 不更新状态行：下一会话会重复领取已完成卡，状态事实源失真。
- 更新状态行：按字面会命中“改动正文区 = 漂移触发器 ⑤”，并会被未来的正文 diff 门禁误报。

ADR-0041 已解决“计划文件可写面”的同类问题，但没有定义任务卡状态行本身。
因此本轮用最窄规则补洞：只允许状态行改变，正文其余内容仍严格只读。

## 决策（一句话）

任务卡分界线以上的 `- 状态：` 行是**正文区唯一可写例外**；Implementer 只能把它改成真实的
任务状态，且必须与产生该状态的提交同批完成，任何其他正文行仍不得改动。

## 决策细化

| # | 内容 |
|---|---|
| **D1 正确定位** | `- 状态：` 行仍是卡片元数据，不因本 ADR 变成自由正文。它只是 ADR-0031 正文只读规则的结构性例外。 |
| **D2 允许写** | 只允许更新该行的状态与必要的同批证据说明；状态值仍使用该卡既有状态词汇（`Ready` / `InProgress` / `Review` / `Done` / `Blocked`）。 |
| **D3 禁止写** | 不得借更新状态行改写目标、In/Out scope、必须遵守、验收命令、DoD、依赖、难度或预估；不得新增或移动分界线。 |
| **D4 同批性** | 状态行更新必须与产生该状态的提交 / PR 同批；禁止“先做完，稍后补状态”。 |
| **D5 唯一性** | 每张卡仍只有一个状态事实源；`plans/*` 的索引表不得新增状态列。 |
| **D6 机器判据** | `card-check` 的正文 diff 判据必须把唯一一条规范状态行排除在正文比较之外；除此之外，分界线以上任何行变化仍是 Error。 |
| **D7 授权修订** | 本 ADR 授权修订 `AGENTS.md` §1/§8、`docs/governance-ai-agent-execution.md` §3.2~§3.4 与 `xtask/src/card_check.rs` 的规则说明，使其与本 ADR 一致。 |

## 考虑过的选项（至少 2 个，含被否理由）

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 状态行继续由 Orchestrator 独家更新 | ❌ 否决 | 与 ADR-0041 已否决的“靠记得同步”同病；Implementer 完成卡后无法同批落状态，会重新制造卡面滞后。 |
| 2 | 把整个 metadata 块都列为可写 | ❌ 否决 | 范围过宽，会让依赖、难度、预估等 Orchestrator 字段被顺手改写，削弱任务卡契约。 |
| 3 | 把状态行移到分界线以下 | ❌ 否决 | 会破坏所有现有卡的格式，且状态行必须在正文开始前可被工具稳定读取；迁移成本远高于明确一个例外。 |
| 4 | 只允许 `- 状态：` 行作为唯一例外 | ✅ **采纳** | 解决实际阻塞，同时把可写面限制在单行；正文保护与 ADR-0041 的原则保持一致。 |

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 把状态行当借口重写正文 | 只允许单行状态行；`card-check` 的正文 diff 判据只排除该行，其他正文变化仍报错。 |
| 状态行与真实状态不一致 | 保留 ADR-0031 D2 的唯一事实源规则，并要求状态更新与产生状态的提交同批。 |
| 工具尚未实现真 git diff 时产生误解 | 本轮明确这是 `card-check` 未来正文 diff 规则的判据；静态扫描行为和测试保持不变。 |
