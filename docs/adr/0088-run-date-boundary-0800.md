# ADR-0088　运行日边界由本地 12:00 提前到 08:00

状态：Accepted　日期：2026-10-13　Supersedes：—　Superseded by：—
关联：ADR-0029 D1（机制）、ADR-0046（一次性任务形态 / D5 抖动建议）、ADR-0050 D5（授权修订 §11.3）、
ADR-0052 D6/D9（边界规则 / `午夜` 日界）、章程 §11.3、`docs/automations/codex-automations-operations.md`
§4.1.c / §6、`docs/audits/automation-26-audit-2026-10-13.md` §3

## 背景

章程 §11.3 定义「运行日」：运行开始时刻在本地 `00:00~11:59` → 归属**前一天**。这条边界是给
「夜间自动化」设计的（23:30 / 02:30 的轮次归到当晚那个运行日），ADR-0029 / ADR-0052 都把它当作
「边界规则」引用（ADR-0052 D6 明确「不改数字预算与边界规则」，ADR-0029 L149 记录其窗口是
`00:00~11:59`）。

问题：`12:00` 这条边界对本项目**白天也会跑**的一次性 automation（ADR-0046 起「任何时间均可」）不合理
—— 本地 08:00~11:59 的开工被压到前一天，与「运行日 = 干活的那一天」冲突，也让「新运行日从 N=1 起」
最早要等到当天 12:00 才生效。人类 2026-10-13 明确指示：**闸门时间提前到早上 8 点**。

## 决策（一句话）

章程 §11.3 的运行日边界由**本地 12:00 提前到本地 08:00**：运行开始时刻在本地 **00:00~07:59**
→ 归属**前一天**；**08:00~23:59** → 归属**当日**。其余 §11.3 规则（轮次计数取 `main`、不覆盖、
N>3 只补报告、每次运行 ≤2 轮）**不变**。

细则：

1. **边界值 12:00 → 08:00**；规则方向与「归属前一天」的语义不变。
2. **抖动建议随之移动**：§11.1 的「避开 00:00 与整点边界至少 10 分钟」改为「避开 08:00 日界与整点边界
   至少 10 分钟」，因为日界翻转点从 12:00 移到了 08:00。
3. **只改规范正文**：章程 §11.3 / §11.1、操作手册 §4.1.c prompt 固定块 + 建后硬核对 + §6 映射。
   历史轮次产物、LEDGER 既有行、ADR-0029 / 0052 正文一律不改（ADR-0051 / 0052 的「历史记录只读」）。
4. **不改机制 / 计数 / 锁 / 报告**：轮次 N 的取数（`main`）、N>3 停止条件、`.automation.lock`、
   阶段报告触发条件全部不动。

## 考虑过的选项（含被否理由）

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 保持 12:00 不变，只在 prompt 里临时放宽 | ❌ 否决 | 章程是唯一事实源；聊天 / prompt 的临时放宽不算数（AGENTS.md「聊天记录不是事实源」），下一个会话重读 §11.3 又退回 12:00 |
| 2 | 直接删掉「归属前一天」，运行日 = 日历日 | ❌ 否决 | 夜间跨日轮次（如 00:30 触发）会与「同一晚的轮次」脱节，破坏既有轮次编号与历史产物一致性 |
| 3 | 把边界设到 05:00（贴合收尾线） | ❌ 否决 | 人类明确指定 08:00；05:00 会让 05:00~07:59 的开工归当天，与「早上开工」意图不符 |
| 4 | **边界 12:00 → 08:00** | ✅ 采纳 | 直接满足「早上 8 点后可开新运行日」；规则方向不变，改动最小；只动数值 + 抖动建议 |

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 历史轮次文件里写的 `00:00~11:59` 与新规则并存，读者混淆 | 历史记录按 ADR-0051 / 0052「只读」保留；本条 + 章程为现行口径；审计 §3 加更正注指向本 ADR |
| 未来 agent 重读 ADR-0029 / 0052 里的 `00:00~11:59` 又按旧值算 | 本 ADR 明确取代这两处的**边界数值**（正文不改，读时以本条为准）；章程 §11.3 是规范落点 |
| 08:00 日界附近的抖动把轮次算错运行日 | §11.1 / §11.3 抖动建议改指 08:00 日界 |

## 验证方式

1. `cargo run -p xtask -- adr-index` → 0 error（0088 登记表 ↔ 文件 ↔ `decisions.md` 一致、下一个可用编号 = 0089）。
2. `cargo run -p xtask -- hygiene / docscan / check-ledger / memory-counts / card-check / refscan` → 全 PASSED。
3. 现行正文扫描：`rg -n "00:00.11:59" docs/automation-charter.md docs/automations/codex-automations-operations.md`
   应 0 命中（历史轮次文件与 ADR-0029 / 0052 正文除外）。
4. 语义复核：本地 02:30 触发 → 运行日 = 前一天；本地 09:30 触发 → 运行日 = 当日。

**重新评估的触发条件**：若未来排期主力时段再次变化（如固定凌晨跑批），再独立评估边界值。
本 ADR 只冻结 08:00 这一个数值。
