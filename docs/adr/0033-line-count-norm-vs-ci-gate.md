# ADR-0033　单文件行数口径：「写作规范 400/600」与「CI 门禁 600/900」的语义划分

状态：**Accepted**（2026-09-18，人类指示 #1 + #11 合并裁决）　日期：2026-09-18　Supersedes：—　Superseded by：—

来源：**PL-033**（gov 内部对「单文件行数」有两套互相矛盾的口径，且与 `AGENTS.md`
也不一致）。关联：`docs/governance-ai-agent-execution.md` §5.4（hygiene 清单里
"file-too-long" 的实装阈值）+ §6.2 (Rust) 模块规模行（写作规范阈值）
+ `AGENTS.md` §5.3（Rust 章节抄的就是 §6.2 (Rust) 那一套）+ `xtask/src/hygiene.rs`
`FILE_LINES_WARN` / `FILE_LINES_ERROR`（= 600 / 900，实装的就是这两条）、
ADR-0032（PL-032 / PL-034 是豁免机制问题，与本文件 ADR-0033 = 不同问题）。

---

## 背景（为什么现在要决定）

实测：仓库里关于「单文件行数上限」的**字面数字**共出现 **3 处**，前两处互相
矛盾，第三处是工具实装。

| 位置 | 字面数字 | 上下文 |
|---|---|---|
| `gov §5.4` | **> 600 行警告，> 900 行失败** | hygiene 表格里的「file-too-long」规则描述 |
| `gov §6.2 (Rust)` 模块规模行 | **单文件 ≤ 400 行（软）/ 600 行（硬）** | 模块规模建议性写法 |
| `AGENTS.md §5.3`（Rust 章节） | **单文件 ≤ 400 行（软）/ 600 行（硬）** | 直接抄 §6.2 (Rust) |
| `xtask/src/hygiene.rs` `FILE_LINES_WARN` / `FILE_LINES_ERROR` | **600 / 900** | 机器实装的就是这两条 |

字面上 §5.4 与 §6.2 (Rust) 互相矛盾（一个说 600 就行，另一个说 600 是硬上限）；
**但它们其实在量的是不同的东西**：

- **400 / 600** = 给**作者**写的「这一坨是不是该拆」建议性上限（写作规范），
  没有任何机器检查会拦截；
- **600 / 900** = 给 **CI** 写的「这个文件太大、挡住 review 了」硬上限
  （门禁），xtask hygiene 的 `file-too-long` 实装的就是它。

后果：按 `AGENTS.md` 读的人会以为 601 行就该拆（硬），按工具跑却只得到
Warning — 两种理解都能自圆其说，于是「拆不拆」变成看谁在场。本轮出现
的真实症状见 ADR-0031 收尾行的 PL-035：人类改了 `AGENTS.md` 三次（167 →
184 → 185 行）每次都触发"超过 400 行硬上限"的纠结，工具却一直 PASSED。

---

## 决策（一句话）

**两套阈值**不矛盾、**各管一摊**：**写作规范 400/600** 留在文档给作者看、
**CI 门禁 600/900** 留给工具抓；只要在两处都**显式标注**"我是写作规范"
或"我是 CI 门禁"，字面差异就不再是矛盾。**不**改成一套统一阈值（理由见
「考虑过的选项」第 3 行）。

拆成四条：

- **D1　官方表述**：本仓库关于单文件行数只有**两套阈值** = 写作规范
  `≤ 400 行（软）/ ≤ 600 行（硬）` + CI 门禁 `> 600 行警告 / > 900 行
  失败`。**两套是互补、不是冲突**：作者先按 400/600 拆，工具按 600/900
  抓超标的。`xtask hygiene` 的 `FILE_LINES_WARN` / `FILE_LINES_ERROR`
  维持 **600 / 900**（**不动**——本 ADR 明确**不改门禁语义**，PL-033 原提
  「本轮不改门禁语义」继承）。

- **D2　gov §5.4 表格行的措辞改述**：在 "file-too-long" 那行**末尾**加
  「**(CI 门禁；作者上限见 §6.2 (Rust) 「模块规模」行 = 400/600)**」。
  **不**改阈值数字本身（保留 600/900），只标注「这是 CI 门禁、不是写作
  规范」，让读 §5.4 的人能一眼看到它与 §6.2 (Rust) 不冲突。

- **D3　gov §6.2 (Rust) 「模块规模」行**上加标注（原本就在 §6.2 (Rust)，不拆动结构）：
  ① 不划出、不重置、不动辊位（少改动 = 少拖雲）；
  ② 在同一行末尾加「**写作规范，不是 CI 门禆**；CI 门禆 = §5.4 的 600/900（ADR-0033）」这一句—— 让读者看到「软 400 / 硬 600」时能顺手看到它与 CI 门禆不冲突。
  ③ 为什么不拆到新节：§6.2 (Rust) 是**Rust 语言专项规范**的一部分，诺多语言不共享「写作规范」这个概念（TypeScript / 其他语言有自己的「组件」要求）；独立成节会造成「谁才是写作规范」的难以回答问题。

- **D4　AGENTS.md §5.3**：同步把 §6.2 (Rust) 模块规模行该行的指向写清——
  原抄录的 "≤ 400 行（软）/ 600 行（硬）"保留（= 写作规范），但**末尾**
  加「(写作规范，CI 门禁见 gov §5.4 = 600/900)」一句；读者第一眼就
  知道这不是门禁数字。

## 考虑过的选项

| # | 方案 | 结论 | 理由 |
|---|---|---|---|
| 1 | **两套阈值各管一摊，并在两处都明确标注「写作规范 / CI 门禁」**（本 ADR 采纳） | ✅ | 字面差异保留，但**语义不冲突**了——400/600 给作者看、600/900 给工具抓，是常见的「建议 vs 强制」双层护栏；不必改任何数字 = 不动门禁语义 = 不漂移 |
| 2 | 统一到 600/900（含 §6.2 (Rust) 改成 600/900） | ❌ | 把"硬上限"从 400 抬到 600 = 放宽写作规范 = 鼓励作者写大文件；与章程 §6.1 的精神相悖（§6.2 (Rust) 原文："单文件 ≤ 400 行（软）/ 600 行（硬）"，"软/硬"分明说明有双层） |
| 3 | 统一到 400/600（含 §5.4 与 xtask 都改成 400/600） | ❌ | 把 CI 门禁从 600/900 收紧到 400/600 = **放宽** xtask 噪音（更小的文件也算"需拆分"，warning/失败线降到 400/600 = 更多文件触发）+ 直接踩 `guard` 类的协作式锁（频繁报警）；PL-033 原提「本轮不改门禁语义」明确否决 |
| 4 | 彻底取消写作规范，只留 CI 门禁（600/900） | ❌ | 取消 §6.2 (Rust) 模块规模行 = 删除「建议性规范」，项目就只能"靠工具吓人"，对人类作者不友好；这是 PL-022 同样的「只留事实源不保留派生建议」反例（写作规范不是派生事实，它是经验总结） |
| 5 | 拆 §5.4 / §6.2 (Rust) 为独立小节后删去「模块规模」整段 | ❌ | 等于选项 4 —— 删建议性规范，理由同 4 |

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 仍然有人读 §5.4 时把 600/900 当成"硬上限 600" | ① D2 的标注（行内 + 节内）；② review agent 固定检查「不要把 600/900 错读为硬 600」；③ ADR-0026 D1 风格的"规则引用登记表"未来可加一行 `[规则, 出现在哪里, 实装阈值]` —— 本轮不实现 |
| 「写作规范 400/600」始终没人看 = 形同虚设 | ① `MEMORY.md` §1 快照的「PL-033 已关闭」一行写明本 ADR 的位置 + 入口；② review agent 在 PR review 时若发现单文件 > 600 行 = 提示"按 §6.2 应拆"（不强制） |
| 后续有人想"统一到一套" | 本 ADR 的「考虑过的选项」明确写**为何不统一**（选项 2/3/4/5 的拒绝理由）—— 写进 ADR 而不是 README，让未来 agent 必须读这个 ADR 才能提"统一" |

## 验证方式（怎么知道这个决策是对的；何时应重新评估）

1. **三处字面数字没动**：gov §5.4 仍是 600/900、§6.2 (Rust) 模块规模行仍是 400/600、`xtask hygiene`
   实装仍是 600/900。检查命令：
   ```bash
   rg -n '600|400|900' docs/governance-ai-agent-execution.md AGENTS.md xtask/src/hygiene.rs
   ```
2. 三处都**显式标注**了自己的角色（CI 门禁 / 写作规范 / CI 门禁实装）；
   上一条命令的命中行里每行末尾或附近都能看到「CI 门禁 / 写作规范 / 实装」。
3. `xtask hygiene` 仍 PASSED、**errors=0**（实装没动，行为不该变）。
4. 全仓 .md 复扫破表 0、setext 0；memory-counts / adr-index PASSED。
5. 重新评估触发条件：① 仓库内**任何文件** ≤ 900 行但 > 600 行 → 若该文件
   实际**不该拆**（如 `xtask/src/main.rs` 这种编排文件），把阈值调成
   「按文件类型分级」—— 但那是选项 2 的变种，仍会改门禁语义；
   ② 「写作规范」被频繁忽略 → 改成机器 lint（等于把 400/600 也变门禁
   —— 又回到选项 3）。两条都是"取消本 ADR"，需要新 ADR。
