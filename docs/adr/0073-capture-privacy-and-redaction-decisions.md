# ADR-0073　截图隐私保持与脱敏决策边界

状态：**Accepted**（2026-10-06，按用户 2026-10-06 预授权代为裁决）　日期：2026-10-06　
Supersedes：ADR-0071 D2 中「正则命中区域」的表述（其余决策不变）　Superseded by：—
关联：ADR-0071、ADR-0063、`crates/platform/api/src/traits/window.rs`、
`crates/dlp/src/redact.rs`、`crates/capture/src/**`、
`tasks/TASK-041-capture-window-redact-privacy.md`

## 背景（为什么现在要决定）

TASK-041 的卡面与 ADR-0071 D2 都写了「密码框 / 正则命中区域」的脱敏模型。
但 `docs/memory/rejected.md` 已在 2026-09-25 否决为了参数校验引入正则引擎：
正则引擎是第三方依赖，且对不可信输入存在 ReDoS 面。截图脱敏若继续把「正则命中」
写进实现目标，会在实现时触发漂移触发器 ①。

同时，`ImageRef` 已明确是「blob 引用 + 宽高」，不是像素本身；平台截图实现尚未落地
（当前 `crates/platform/windows` 的 `capture()` 仍返回 `CapabilityMissing`）。
因此本轮只能冻结像素与决策的归属、隐私模式语义、滚动清理的上界，并实现零依赖纯逻辑。

## 决策（一句话）

**`crates/capture` 只做平台无关编排与规则应用决策，不做像素遮挡；`never persist`
模式不得返回或保留 `ImageRef`；滚动清理只产生有界计划、不调用平台；文本命中只接受
调用方已判定的区间或显式词表，不引入正则引擎。**

## 决策细化

| # | 内容 |
|---|---|
| **D1** | `ImageRef` 仍是平台层返回的 blob 引用与宽高，像素级遮挡、图像编解码和实际 blob 生命周期都归 `crates/platform/*`。`crates/capture` 不读取、修改或重新编码像素，也不直接调用任何平台 API；它只消费 `WindowProvider::capture` 的结果并产出可审计的遮挡矩形决策。 |
| **D2** | 本轮不修改 `WindowProvider::capture` / `CaptureOptions` / `ImageRef` 的公共形状。平台实现何时、如何应用 `CaptureOptions.redact` 由后续平台卡按已冻结接口决定；纯逻辑层不得假装平台已完成像素遮挡。 |
| **D3** | 隐私模式 `NeverPersist` 的语义是：管线不构造、不返回、不保留 `ImageRef`。若注入的 `WindowProvider` 已经返回引用，管线只能读取其宽高后立即丢弃，输出中 `retained_image` 必须为 `None`；`PersistBlob` 才允许把引用保留在输出中。 |
| **D4** | 滚动清理是编排计划，不是平台调用。计划必须显式携带合并方向（从上到下或从下到上）、重叠像素和步数；步数有硬上限，零步或超上限必须显式失败。实际滚动、截图和拼接由后续平台/执行卡实现。 |
| **D5** | 脱敏规则只有两个显式来源：密码框等**调用方已判定区域**，以及文本扫描器传入的**已判定命中区间**。`crates/dlp` 不接收正则表达式、不实现词法扫描。若未来需要文本前缀词表，词表也由调用方在进入 `redact` 前完成命中判定；本 ADR 不引入表达式语言。 |
| **D6** | 规则解析 fail-closed：空规则列表、负坐标、零宽高、越界区域、坐标溢出和超过规则上限都必须返回显式错误；不得静默跳过敏感区域，也不得用默认矩形冒充结果。 |
| **D7** | 脱敏决策是有界的：规则表采用固定上限，滚动计划采用固定步数上限。任何未来缓存或长期状态仍受 ADR-0063 约束。 |
| **D8** | 本 ADR 只冻结 TASK-041 拆分 A 的纯逻辑边界；不改公共 schema、不改 `platform/api` trait、不新增 crate、不新增第三方依赖、不 `#[allow]`、不 `unsafe`。 |

## 考虑过的选项（至少 2 个，含被否理由）

| # | 选项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 在 `crates/dlp` 内引入正则引擎并让规则表直接写正则 | ❌ 否决 | 违反 `docs/memory/rejected.md` 的 2026-09-25 裁决；新增第三方依赖、引入 ReDoS 面，并把不可信文本匹配逻辑塞进脱敏模型。 |
| 2 | 让 `crates/capture` 自己解码和修改像素，再返回已遮挡图像 | ❌ 否决 | 违反 ADR-0071 D1/D4 与铁律 7；纯 Rust 编排层会重复平台能力，并把 blob 生命周期和像素所有权拉进来。 |
| 3 | 扩展 `CaptureOptions` 让管线传入遮挡矩形 | ❌ 否决（本轮） | 会改公共 trait / schema，属于漂移触发器 ③；且平台截图实现尚未落地，先冻结纯逻辑更安全。 |
| 4 | **只实现决策与有界计划，平台后续消费规则** | ✅ **采纳** | 零依赖、零公共接口变化，能先锁定隐私与失败语义，并为后续平台卡留下清晰边界。 |

## 影响

- `crates/dlp/src/redact` 可提供纯规则模型与遮挡矩形计算；不新增依赖。
- `crates/capture` 可编排 `WindowProvider::capture`，按隐私模式决定输出是否保留 `ImageRef`，
  并可生成有界滚动计划；不直接调平台、不读像素。
- TASK-041 的后续拆分仍可在平台层实现真实截图与像素遮挡；本 ADR 不宣称该部分已完成。
- ADR-0071 的 crate 边界、依赖方向、零第三方依赖起步和 ADR-0063 的有界纪律保持不变；
  仅其 D2 中「正则命中区域」的措辞由本 ADR 替换为「已判定区间 / 显式词表」。
